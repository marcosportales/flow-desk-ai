# Permission comes from Team membership; assignment is accountability

Any Operator of a Ticket's Team may run its Manual Actions, whether or not they are its Assignee. Assignment is pull-based (an Operator takes a Ticket from the Team's queue; any Operator of the Team can release or reassign it) and only decides who is accountable and who is notified. A Ticket with no Category yet (Manual Review) belongs to `service_desk`. The API key identifies an Integration, which may create and read Tickets but cannot run Manual Actions: those routes require an Operator session, enforced in Server Actions and API routes, not just hidden in the UI. We rejected "only the Assignee may act" because it blocks cover for an absent colleague, and automatic round-robin assignment because it adds scheduling rules the demo does not need.
