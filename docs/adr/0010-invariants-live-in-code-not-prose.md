# Invariants live in code and checks, not in prose

Most of this codebase is written by agents, which copy whatever pattern already exists and take the shortest path to green. So a rule that matters is made true by construction, or failing that by a check, before it is written down: first the code's shape (one function is the only way to change a Ticket Status and append its Ticket Event; one wrapper is the only way to run a Manual Action; Ticket Event types and data are a typed union), then static checks run in CI (ESLint import boundaries between `src/domain`, `src/services`, `src/infra` and `src/app`; architecture tests; typecheck; the test suite), and only what needs judgement goes into prose (`CLAUDE.md`, skills, comments), kept short. Human review is spent on that environment rather than on catching the same slip in every PR, and a mistake that recurs in review becomes a type, a lint rule or a test, not another paragraph. We rejected relying on `CLAUDE.md` rules and review alone because neither scales with how fast agents land code, and fixes such as a forgotten `revalidatePath` (SCRUM-21) kept coming back.
